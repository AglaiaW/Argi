# PRD: 超级社区生态层

## 1. Introduction / Overview

超级社区是蔚蓝 OPC 平台的生态层，用来把创作、交易、竞技和协作连接为同一个用户系统。它不是附属功能，而是平台价值放大的关系网络，帮助用户解决四个连续问题：

- 在平台内被看见
- 在市场中被需要
- 在赛事中被认可
- 在圈子中被连接

社区底部 Tab 进入后，默认进入“发现”，并通过四个一级板块承载完整生态：

- 发现：内容和人的匹配层
- 市场：能力和需求的交易层
- 赛事：创意和荣誉的竞技层
- 圈子：兴趣和协作的关系层

## 2. Goals

- 将社区升级为四大板块联动的完整生态入口，而不是单一信息流页面。
- 让用户能在一次浏览过程中完成“发现内容 → 进入交易/赛事/圈子”的跳转闭环。
- 统一作品、模板、赛事、圈子的视觉语言和对象模型。
- 为后续的推荐、成交、荣誉体系和私域关系沉淀提供稳定前端结构。
- 在 MVP 中先完成社区首页层的内容架构和可交互壳层，而不引入真实后端数据。

## 3. User Stories

### US-001: 社区一级导航
**Description:** 作为平台用户，我希望进入社区后能清楚看到“发现、市场、赛事、圈子”四个一级板块，这样我能快速进入自己要找的内容场景。

**Acceptance Criteria:**
- [ ] 社区页顶部展示四个一级 Tab：发现、市场、赛事、圈子
- [ ] 默认选中“发现”
- [ ] 切换一级 Tab 时页面内容同步变化
- [ ] 当前选中 Tab 有明确高亮状态
- [ ] Typecheck / lint passes
- [ ] Verify in browser using dev-browser skill

### US-002: 发现页推荐流
**Description:** 作为创作者，我希望在发现页看到作品、模板动态、赛事动态和圈子招募混合信息流，这样我能快速了解社区热点并进入相关详情。

**Acceptance Criteria:**
- [ ] 发现页包含关注 / 推荐 / 热门三级切换
- [ ] 发现页包含 Banner 运营位
- [ ] 信息流至少包含四类卡片：作品、模板上新、赛事动态、圈子招募
- [ ] 发布按钮点击后出现发布面板，而不是直接切页
- [ ] Typecheck / lint passes
- [ ] Verify in browser using dev-browser skill

### US-003: 市场页交易入口
**Description:** 作为想买模板或卖模板的用户，我希望看到清晰的搜索、筛选、分类和模板卡片流，这样我能快速找到能直接使用的能力包。

**Acceptance Criteria:**
- [ ] 市场页包含搜索栏和筛选入口
- [ ] 市场页包含分类标签和排序栏
- [ ] 模板卡片展示封面、名称、作者、类型、价格、销量、评分和作者收益
- [ ] 页面包含“我的交易”入口
- [ ] Typecheck / lint passes
- [ ] Verify in browser using dev-browser skill

### US-004: 赛事页荣誉入口
**Description:** 作为希望参赛或关注平台荣誉体系的用户，我希望快速看到主推赛事、状态筛选和赛事卡片流，这样我能决定报名、关注或查看历史成果。

**Acceptance Criteria:**
- [ ] 赛事页包含主推 Banner
- [ ] 赛事页包含状态筛选：全部 / 报名中 / 进行中 / 评审中 / 已结束
- [ ] 赛事列表卡片展示状态、类型、奖池、人数和时间范围
- [ ] 页面展示赛事类型说明和历届价值说明
- [ ] Typecheck / lint passes
- [ ] Verify in browser using dev-browser skill

### US-005: 圈子页关系入口
**Description:** 作为平台用户，我希望在圈子页看到我的圈子、推荐圈子、活跃榜和分类筛选，这样我能找到适合长期协作的共同体。

**Acceptance Criteria:**
- [ ] 圈子页展示“我的圈子”横向列表
- [ ] 圈子页展示推荐圈子和活跃榜
- [ ] 圈子页包含分类筛选和圈子卡片流
- [ ] 页面包含“+ 创建圈子”入口
- [ ] Typecheck / lint passes
- [ ] Verify in browser using dev-browser skill

### US-006: 统一对象跳转语义
**Description:** 作为用户，我希望不同板块的卡片都能明确告诉我点击后会去哪里，这样我不会因为页面信息复杂而迷失。

**Acceptance Criteria:**
- [ ] 作品卡指向作品详情
- [ ] 模板卡指向市场模板详情
- [ ] 赛事卡指向赛事详情
- [ ] 圈子卡指向圈子主页
- [ ] 卡片上有足够的辅助文案说明对象属性
- [ ] Typecheck / lint passes

### US-007: 统一发布入口
**Description:** 作为创作者，我希望通过一个统一发布入口完成作品发布、模板上架、圈子动态分享和赛事投稿，这样我不需要记住多套入口。

**Acceptance Criteria:**
- [ ] 发现页右侧“+”按钮可打开发布面板
- [ ] 发布面板至少包含四个动作：发布作品、上架模板、分享动态到圈子、提交赛事作品
- [ ] 发布面板支持关闭返回
- [ ] Typecheck / lint passes
- [ ] Verify in browser using dev-browser skill

### US-008: MVP 内容边界
**Description:** 作为产品和开发团队，我希望社区页先完成结构化展示和交互壳层，这样可以先验证信息架构，再接真实数据与详情页。

**Acceptance Criteria:**
- [ ] 当前实现仅为前端展示层，不依赖后端真实接口
- [ ] 不实现交易支付、报名提交、圈聊 IM、审批流等重交互系统
- [ ] 所有模块内容使用可替换的静态数据驱动
- [ ] Typecheck / lint passes

## 4. Functional Requirements

- FR-1: 社区作为底部主导航中的独立一级入口，默认进入“发现”。
- FR-2: 社区页顶部必须提供四个一级板块 Tab：发现、市场、赛事、圈子。
- FR-3: 发现页必须包含关注 / 推荐 / 热门三级流量视图切换。
- FR-4: 发现页必须包含 2-3 张轮播 Banner，内容覆盖赛事、官方活动和圈子招募。
- FR-5: 发现页信息流必须混排四类卡片：作品内容、模板上新、赛事动态、圈子招募。
- FR-6: 发现页发布按钮点击后必须弹出发布面板，而不是直接跳到其它页面。
- FR-7: 市场页必须包含搜索栏、筛选入口、分类标签、排序栏和模板卡片流。
- FR-8: 市场页模板卡片必须展示：封面图、模板名、作者信息、类型、价格、销量、评分、作者收益。
- FR-9: 市场页必须包含“我购买的 / 我上架的”交易入口展示。
- FR-10: 赛事页必须包含主推 Banner、状态筛选和赛事卡片流。
- FR-11: 赛事卡片必须展示：封面、赛事名、状态、类型、奖池概要、报名人数、时间范围。
- FR-12: 赛事页必须展示赛事类型说明，用于解释不同比赛的价值差异。
- FR-13: 圈子页必须包含“我的圈子、推荐圈子、活跃榜、分类筛选、圈子卡片流、创建入口”。
- FR-14: 圈子卡片必须展示：头像、名称、简介、成员数、本周动态数、标签、加入方式。
- FR-15: 圈子页必须为后续“圈子主页 / 圈内动态 / 圈内资产 / 圈内活动”预留入口表达。
- FR-16: 各类卡片点击语义必须统一并显式指向各自详情页目标。
- FR-17: 所有社区模块在视觉上必须使用统一的信息层级、标签样式和卡片语言。

## 5. Non-Goals

- 不实现真实交易购买、支付、退款、订阅计费。
- 不实现真实赛事报名、作品提交、评审后台和榜单结算。
- 不实现完整圈聊 IM、消息送达、已读状态。
- 不实现圈主审批流、管理员分配、成员审核逻辑。
- 不实现真实推荐算法，仅展示推荐位和解释位的结构。
- 不在本期实现模板详情页、赛事详情页、圈子主页的完整内部页面。

## 6. Design Considerations

- 社区一级导航必须明显区别于左侧应用级导航，避免层级混淆。
- 发现页仍然承担“社区首页”职责，不额外增加总览首页。
- 视觉上要保持统一蓝绿科技品牌，但避免过重炫技导致信息难读。
- 卡片需要明确“这是什么、为什么推荐给我、点击后去哪”三层语义。
- 市场、赛事、圈子三页应与发现页形成同一品牌体系，但内容布局必须有明显职能差异。

## 7. Technical Considerations

- 当前仓库是单文件 `src/App.tsx` 的 React + Vite 原型，社区模块优先在现有 `Discovery` 组件内升级为完整“社区壳层”。
- 本期可以继续使用静态数组驱动页面内容，但应按对象类型拆分数据，以便后续接真实接口。
- 推荐将社区状态拆成两层：`一级板块` + `发现页子流切换`。
- 发布面板建议继续使用当前已有的底部滑出层思路，而不是新增路由。
- 需要兼顾桌面与移动端布局，不允许一级板块在小屏下完全失效。

## 8. Success Metrics

- 用户进入社区后，能够在 3 秒内识别四个一级板块各自用途。
- 用户从发现页任一信息流卡片都能理解点击后的去向。
- 用户能在一次访问中完成至少一次跨板块认知跳转，例如“发现作品 → 查看市场模板”。
- 社区页面在视觉上从“单页 Demo”升级为“生态入口”，具备后续接真实系统的壳层价值。

## 9. Open Questions

- 发现页是否需要为推荐结果增加“推荐原因”文案行，作为下一阶段增强项。
- 市场页的“我的交易”入口最终是底部悬浮还是页内固定栏，目前前端演示层可先做页内入口。
- 圈子内部的“圈聊”未来是否做成独立面板，还是只作为圈子主页中的轻量模块。
- 赛事详情页未来是否需要和圈子联动，例如自动生成“赛事讨论圈”。
